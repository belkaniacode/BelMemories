## Где что лежит

| Что | Linux | Windows |
|---|---|---|
| Настройки | `~/.config/BelMemories/settings.json` | `%AppData%\BelMemories\settings.json` |
| Логи (ротация 10 МБ × 5) | `~/.config/BelMemories/logs/app.log` | `%AppData%\BelMemories\logs\app.log` |
| Отчёты пробных запусков | `~/.config/BelMemories/reports/` | `%AppData%\BelMemories\reports\` |
| Индекс архива | `<архив>/.memoryarchive/index.db` | то же |
| Отчёты запусков (JSON + CSV) | `<архив>/.memoryarchive/reports/` | то же |
| Временные файлы копирования | `<архив>/.memoryarchive/tmp/*.part` | то же |

Папку `.memoryarchive` не удаляйте: без индекса программа не узнает, какие файлы уже в архиве. Если индекс всё же потерян, на экране «Назначение» появится кнопка «Построить индекс».

## settings.json

Файл заполняется из окна программы. Вручную его обычно править не нужно.

| Поле | По умолчанию | Назначение |
|---|---|---|
| `load` | `medium` | Уровень нагрузки: `low`, `medium`, `high` |
| `verifyAfterCopy` | `true` | Перечитывать каждый записанный файл и сверять хэш |
| `bytesPerSecLimit` | `0` | Свой лимит скорости чтения в байтах/с; `0` — по уровню нагрузки |
| `clipThreshold` | `0.5` | С какой уверенности нейросети изображение идёт в «Картинки» (0–1). Больше — строже |
| `modelDir` | `""` | Своя папка с моделью CLIP; пусто — автопоиск |
| `theme` | `auto` | Тема: `light` или `dark`. `auto` значит, что тема ещё не выбрана (см. ниже) |
| `knownArchives` | `[]` | Заполняется автоматически: архивы, в которые программа уже копировала (новые первыми, не больше 50). Используются для поиска дублей, см. ниже |
| `recentSources` | `[]` | Три последних источника |
| `lastDestination` | `""` | Последняя выбранная папка назначения |

Старое поле `otherArchives` (ручной список других архивных дисков) и `lastDestination` при загрузке переносятся в `knownArchives`; `otherArchives` после этого удаляется из файла.

Если файл повреждён, программа переименует его в `settings.json.bak` и запустится с настройками по умолчанию.

## Тема

Тем две: светлая и тёмная. При первом запуске (`theme` = `auto`) программа один раз определяет тему системы:

- **Linux**: ключ `color-scheme` в `gsettings` (GNOME, KDE и большинство современных окружений), затем `ColorScheme` в `~/.config/kdeglobals`, затем переменная `GTK_THEME` и тема GTK из `gsettings`. Если ничего не найдено — светлая.
- **Windows**: параметр реестра `AppsUseLightTheme` (`HKCU\Software\Microsoft\Windows\CurrentVersion\Themes\Personalize`).

Дальше тема переключается кнопкой с солнцем или луной в правом верхнем углу окна, выбор сохраняется в `theme`. Последующие изменения темы системы программа не отслеживает.

## Язык интерфейса

Интерфейс доступен на русском и английском. Язык выбирается при запуске по языку системы: русский, если язык системы русский, иначе английский. Отдельной настройки нет.

Имена папок в архиве (`Фото`, `Видео`, `Картинки`, `Без даты`) пока от языка не зависят и остаются русскими.

## Недавние источники

Запоминаются только три последних источника. На экране «Источник» они показываются одной строкой в виде коротких кнопок; список можно очистить. После настоящей (не пробной) архивации выбранные источники сбрасываются, чтобы следующий запуск не захватил их повторно незаметно. Кнопка «Новая архивация» на экране отчёта сбрасывает весь мастер: источники, результаты сканирования и отчёт.

## Дубли между архивами

Отдельной настройки для других архивных дисков нет. Перед каждым запуском программа проверяет дубли по:

- всем архивам из `knownArchives` (сюда попадает каждая папка, в которую прошла настоящая архивация);
- архивам в корне подключённых дисков (где есть `.memoryarchive/index.db`).

Другие архивы открываются только для чтения. Отключённые диски тихо пропускаются.

## Экран «Назначение»

Для выбранной папки показывается:

- свободное место на диске;
- сколько файлов и байт будет скопировано. Файлы, которые уже физически лежат в архиве, не считаются. Оценка идёт по размеру, поэтому это верхняя граница;
- сколько файлов уже физически лежит в папке (считаются файлы на диске, а не записи индекса).

Запас в 1 ГиБ в сумму «будет скопировано» не входит, но учитывается при проверке «места хватает»: нужно свободное место не меньше объёма копирования плюс 1 ГиБ. Во время архивации запуск останавливается, если после записи очередного файла останется меньше 1 ГиБ.

## Уровни нагрузки

| Уровень | Потоки анализа | Параллельные чтения | Лимит скорости | Приоритет диска |
|---|---|---|---|---|
| Низкая | 1 | 1 | 40 МБ/с | фоновый (idle) |
| Средняя | min(4, ядра/2) | 1 | нет | пониженный |
| Высокая | ядра − 1 | 2 | нет | пониженный |

На всех уровнях приоритет процессора снижен (nice 10 на Linux, фоновый режим на Windows). Для внешних HDD рекомендуются «Низкая» или «Средняя»: диск читается последовательно и не «трещит».

## Логи

Подробность задаётся переменной окружения `LOG_LEVEL`:

```bash
LOG_LEVEL=debug ./BelMemories   # решение по каждому файлу: дата, категория, дубль
```

| Значение | Что пишется |
|---|---|
| `error` | только ошибки |
| `warn` | + пропущенные файлы, проблемы доступа |
| `info` (по умолчанию) | + старт/финиш запусков, прогресс каждые 1000 файлов |
| `debug` | + подробности по каждому файлу |

Формат записей JSON, поля `component`, `path`, `err`.

## Нейросеть CLIP

Модель ищется в таком порядке: `modelDir` из настроек, папка `models/` рядом с программой, `./models`, `<конфиг>/BelMemories/models`. Библиотека `onnxruntime` ищется рядом с программой, в `models/lib/`, затем в системных путях.

Если чего-то не хватает, программа работает только по правилам. На экране «Назначение» это видно по метке «только правила» с указанием причины.
